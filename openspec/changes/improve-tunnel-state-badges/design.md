## Context

当前新控制台首页列表使用统一的浅蓝色徽标样式来显示不同的隧道状态，虽然文案会变化，但视觉层面没有充分表达状态差异。项目已经在 viewmodel 中汇总了 `TunnelSnapshot.State` 和 `LastError`，因此可以在不调整控制器状态机的前提下，通过 UI 层增加状态语义映射。

## Goals / Non-Goals

**Goals:**
- 为列表状态徽标建立稳定的一套颜色语义。
- 让连接失败态能够在首页列表被直接识别，而不是必须点进详情页看日志。
- 保持现有文案和状态机不变，避免扩大行为变更范围。

**Non-Goals:**
- 不修改隧道控制器的状态枚举。
- 不引入动画、额外图标或复杂的告警提示。
- 不在本次变更中重构详情页或日志页的状态展示样式。

## Decisions

### 1. 在 viewmodel 中增加状态样式类别
列表项除了已有的 `StateLabel`，再增加一个 `StateTone` 或类似字段，由 UI adapter 根据快照状态和错误信息计算。页面层只负责渲染对应 CSS class，不在模板中重复判断业务状态。

### 2. 失败态优先于“未连接”文案
当 snapshot 当前不是 connected，但存在 `LastError` 时，首页列表应以“失败”语义渲染红色徽标。这样可以在状态机仍保留 `disconnected` 时，把最近一次失败结果明确表达给用户。

### 3. 颜色映射保持简单稳定
- disconnected 且无错误：灰色
- connecting / retrying：蓝色
- connected：绿色
- disconnected 且有错误：红色

这样不引入新的公开状态枚举，只是增强现有状态的视觉表达。

## Risks / Trade-offs

- [失败态依赖 LastError，可能在某些主动停止场景下仍显示灰色而非红色] → 保持“有错误才红色”的规则，避免把用户主动停止误判为故障。
- [列表颜色和详情页当前状态样式不完全一致] → 本次先覆盖用户关注最强的首页列表，后续如果需要再统一到详情页。
