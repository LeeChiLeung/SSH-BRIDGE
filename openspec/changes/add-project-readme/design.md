## Context

这个项目已经从单文件 SSH 本地转发器演进为具备以下能力的桌面化工具：多实例 tunnel profile、本地 Web 控制台、系统托盘入口、流量统计、版本注入和多平台构建。仓库目前没有 `README.md`，导致使用方式只能依赖即时沟通或查看源码与 OpenSpec 变更目录。

README 的实现本身不复杂，但它横跨 CLI、WebUI、打包、版本、配置持久化和已知平台限制，属于跨模块的文档整理工作，适合先明确文档结构和取材边界，再进入编写。

## Goals / Non-Goals

**Goals:**
- 提供一份与当前代码行为一致的项目入口文档。
- 同时覆盖“我是用户，如何运行”和“我是维护者，如何构建发布”两类核心路径。
- 明确版本控制、默认端口、默认 profile 存储位置、产物类型和当前平台限制。
- 保持 README 务实，优先写当前已经稳定存在的能力。

**Non-Goals:**
- 不为未来尚未实现的能力编写预告式文档。
- 不编写过度细化的架构白皮书或逐文件源码导览。
- 不在这次变更里补充 CI、截图生成、徽章或多语言文档。

## Decisions

### 1. README 采用“先上手、后细节”的结构
README 将优先给出项目简介、核心能力、快速开始和常用命令，再补充配置存储、打包发布和已知限制。

Rationale:
- 新用户首先需要回答“这是什么、怎么跑起来”。
- 构建和版本信息对维护者重要，但不应压到文档最前面。

Alternatives considered:
- 按模块分章节罗列所有源码能力，但可读性较差，也不利于第一次使用。

### 2. 所有示例都以当前默认行为为准
README 中的示例将使用当前实现中的默认 Web 地址 `127.0.0.1:8848`、默认托盘入口、`scripts/release.sh` 打包脚本和 `--version` 命令。

Rationale:
- 文档的首要价值是可直接复制执行。
- 避免文档继续残留历史阶段的 `8080`、`--web` 默认启动或旧打包方式。

Alternatives considered:
- 只给抽象说明，不给具体命令；这样更“通用”，但会降低可执行性。

### 3. README 显式记录当前已知平台限制
README 将明确说明：当前默认打包矩阵为 Linux/Windows，macOS 构建已从默认矩阵中移除，因为现有托盘依赖在当前 Linux 环境下无法直接完成 Darwin 交叉构建。

Rationale:
- 这是当前真实状态，必须提前告诉操作者。
- 避免用户误以为缺失产物是脚本错误。

Alternatives considered:
- 在 README 中省略平台限制，仅在 issue 或聊天中说明；这会增加重复沟通成本。

## Risks / Trade-offs

- [文档与代码逐渐漂移] → README 只记录当前稳定存在的行为，并引用实际命令、默认值和路径，减少主观描述。
- [信息过长影响首屏可读性] → 采用分层结构，优先快速开始，再展开高级内容。
- [历史实现细节残留在文档中] → 编写时以当前代码与打包脚本为唯一依据，不沿用旧命令。

## Migration Plan

这项变更只新增文档，无运行时迁移步骤。合入后，仓库首页即可直接使用 README 作为主入口文档。
